# Dynamic-Claster-Managment

Кластер из k узлов на C. Узлы общаются между собой, следят кто живой, новые можно добавлять на ходу, старые убирать.

## Сборка

Нужен gcc и make, всё под linux (posix сокеты, pthread). На винде через WSL.

    make

Бинарник будет в build/node.

## Запуск

Первый узел просто поднимаем:

    ./build/node --port 5000

Остальные цепляем к любому живому:

    ./build/node --port 5001 --join 127.0.0.1:5000
    ./build/node --port 5002 --join 127.0.0.1:5001

Новый узел получает список остальных и сам к ним подключается.

Команды в консоли узла:

- `peers` - список узлов и их состояние
- `send <id> <text>` - отправить сообщение узлу
- `leave` - выйти из кластера по-нормальному

Если узел просто убить (ctrl+c, kill -9), остальные через несколько секунд заметят по хартбитам и пометят его мертвым.

## Как устроено

Все узлы равноправные, центрального нет. Каждый слушает tcp порт и держит соединение с каждым (full mesh, для пары десятков узлов хватает).

Сообщение = заголовок фиксированного размера (тип, флаги, длина) + payload. Типы:

- HELLO / WELCOME - вход в кластер, в ответ приходит список узлов
- PEER_JOINED / PEER_LEFT - состав поменялся
- PING / PONG - хартбит
- DATA - просто данные

Мониторинг: раз в N секунд пингуем всех. Нет ответа дольше таймаута - SUSPECT, еще дольше - DEAD, выкидываем из таблицы.

Расширения (шифрование и т.п.) вешаются как хуки на отправку/прием. Перед отправкой payload прогоняется через цепочку хуков, при приеме в обратном порядке. Флаги в заголовке говорят какие хуки применялись. Само шифрование пока не сделано, но место под него есть.

## Структура

    src/
      main.c       - аргументы, консоль
      node.c/.h    - таблица узлов, join/leave
      net.c/.h     - сокеты, отправка/прием
      proto.c/.h   - формат сообщений
      monitor.c/.h - хартбиты, таймауты
      ext.c/.h     - хуки для расширений
    Makefile
